Speedrun CLI (1 min lectura)

Todo el taller por AWS CLI, por si toca ir rápido o defender qué hace cada comando. Corre en orden; cada bloque guarda el ID que necesita el siguiente.

1. Identidad y región

aws sts get-caller-identity
aws configure set region us-east-1

Confirma quién eres y fija la región para no crear recursos en otro lado por accidente.

2. Baseline Lab 01: VPC y subnets

VPC_ID=$(aws ec2 create-vpc --cidr-block 10.20.0.0/16 \
  --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=dcl-dev-vpc},{Key=dcl:project,Value=digital-cafe-luna},{Key=dcl:environment,Value=dev},{Key=dcl:owner-team,Value=team-01}]' \
  --query 'Vpc.VpcId' --output text)

SUB_A=$(aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.20.1.0/24 \
  --availability-zone us-east-1a \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=dcl-dev-subnet-a}]' \
  --query 'Subnet.SubnetId' --output text)

SUB_B=$(aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.20.2.0/24 \
  --availability-zone us-east-1b \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=dcl-dev-subnet-b}]' \
  --query 'Subnet.SubnetId' --output text)

Si ya existe el baseline, saltar este bloque y solo recuperar los IDs con describe-vpcs / describe-subnets filtrando por el tag dcl:project.

3. Conectividad: Internet Gateway y ruta pública

IGW_ID=$(aws ec2 create-internet-gateway \
  --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=dcl-dev-igw-s02}]' \
  --query 'InternetGateway.InternetGatewayId' --output text)
aws ec2 attach-internet-gateway --vpc-id $VPC_ID --internet-gateway-id $IGW_ID

RT_ID=$(aws ec2 create-route-table --vpc-id $VPC_ID \
  --tag-specifications 'ResourceType=route-table,Tags=[{Key=Name,Value=dcl-dev-rt-s02-public}]' \
  --query 'RouteTable.RouteTableId' --output text)
aws ec2 create-route --route-table-id $RT_ID --destination-cidr-block 0.0.0.0/0 --gateway-id $IGW_ID
aws ec2 associate-route-table --route-table-id $RT_ID --subnet-id $SUB_A
aws ec2 associate-route-table --route-table-id $RT_ID --subnet-id $SUB_B

El ALB internet-facing exige un Internet Gateway en la VPC; la ruta 0.0.0.0/0 hace que las dos subnets salgan a internet.

4. Security groups

SG_ALB=$(aws ec2 create-security-group --group-name dcl-dev-sg-alb --description "ALB" \
  --vpc-id $VPC_ID --query 'GroupId' --output text)
aws ec2 authorize-security-group-ingress --group-id $SG_ALB --protocol tcp --port 80 --cidr 0.0.0.0/0

SG_APP=$(aws ec2 create-security-group --group-name dcl-dev-sg-app --description "App" \
  --vpc-id $VPC_ID --query 'GroupId' --output text)
aws ec2 authorize-security-group-ingress --group-id $SG_APP --protocol tcp --port 80 --source-group $SG_ALB

El ALB recibe HTTP de cualquiera; las instancias solo aceptan HTTP que venga del SG del ALB, nunca directo de internet.

5. Launch Template, Target Group y ALB

AMI_ID=$(aws ssm get-parameters --names /aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64 \
  --query 'Parameters[0].Value' --output text)

USER_DATA=$(base64 <<'EOF'
#!/bin/bash
set -euxo pipefail
dnf install -y httpd
TOKEN=$(curl -sS -X PUT -H "X-aws-ec2-metadata-token-ttl-seconds: 21600" http://169.254.169.254/latest/api/token)
IID=$(curl -sS -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/instance-id)
AZ=$(curl -sS -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/placement/availability-zone)
echo "Digital Café Luna | instance=${IID} | az=${AZ}" > /var/www/html/index.html
systemctl enable --now httpd
EOF
)

LT_ID=$(aws ec2 create-launch-template --launch-template-name dcl-dev-lt-web \
  --launch-template-data "{\"ImageId\":\"$AMI_ID\",\"InstanceType\":\"t3.micro\",\"UserData\":\"$USER_DATA\",\"NetworkInterfaces\":[{\"DeviceIndex\":0,\"AssociatePublicIpAddress\":true,\"Groups\":[\"$SG_APP\"]}]}" \
  --query 'LaunchTemplate.LaunchTemplateId' --output text)

TG_ARN=$(aws elbv2 create-target-group --name dcl-dev-tg-web --protocol HTTP --port 80 \
  --vpc-id $VPC_ID --health-check-path / --healthy-threshold-count 2 --health-check-interval-seconds 10 \
  --query 'TargetGroups[0].TargetGroupArn' --output text)

ALB_ARN=$(aws elbv2 create-load-balancer --name dcl-dev-alb --type application \
  --subnets $SUB_A $SUB_B --security-groups $SG_ALB \
  --query 'LoadBalancers[0].LoadBalancerArn' --output text)

aws elbv2 create-listener --load-balancer-arn $ALB_ARN --protocol HTTP --port 80 \
  --default-actions Type=forward,TargetGroupArn=$TG_ARN

Launch Template define cómo nace cada instancia (AMI, tipo, SG, user data). Target Group decide quién es elegible. ALB expone un único endpoint y reparte tráfico hacia el Target Group.

6. Auto Scaling Group

aws autoscaling create-auto-scaling-group --auto-scaling-group-name dcl-dev-asg-web \
  --launch-template LaunchTemplateId=$LT_ID,Version='$Latest' \
  --min-size 2 --desired-capacity 2 --max-size 4 \
  --target-group-arns $TG_ARN \
  --vpc-zone-identifier "$SUB_A,$SUB_B" \
  --health-check-type EC2

min/desired/max=2/2/4, health check EC2 (no ELB), sin scaling policy: solo queremos ver que mantiene desired, no que escale por demanda.

7. Probar y limpiar

ALB_DNS=$(aws elbv2 describe-load-balancers --names dcl-dev-alb --query 'LoadBalancers[0].DNSName' --output text)
for i in {1..20}; do curl -s "http://${ALB_DNS}"; echo; done | sort | uniq -c

# terminar una instancia y observar reemplazo
IID=$(aws autoscaling describe-auto-scaling-groups --auto-scaling-group-names dcl-dev-asg-web \
  --query 'AutoScalingGroups[0].Instances[0].InstanceId' --output text)
aws ec2 terminate-instances --instance-ids $IID

# cleanup obligatorio, en orden
aws autoscaling update-auto-scaling-group --auto-scaling-group-name dcl-dev-asg-web --min-size 0 --desired-capacity 0
aws autoscaling delete-auto-scaling-group --auto-scaling-group-name dcl-dev-asg-web --force-delete
aws elbv2 delete-load-balancer --load-balancer-arn $ALB_ARN
aws elbv2 delete-target-group --target-group-arn $TG_ARN
aws ec2 delete-launch-template --launch-template-id $LT_ID
aws ec2 revoke-security-group-ingress --group-id $SG_APP --protocol tcp --port 80 --source-group $SG_ALB
aws ec2 delete-security-group --group-id $SG_APP
aws ec2 delete-security-group --group-id $SG_ALB
aws ec2 disassociate-route-table --association-id $(aws ec2 describe-route-tables --route-table-ids $RT_ID --query 'RouteTables[0].Associations[0].RouteTableAssociationId' --output text)
aws ec2 delete-route-table --route-table-id $RT_ID
aws ec2 detach-internet-gateway --internet-gateway-id $IGW_ID --vpc-id $VPC_ID
aws ec2 delete-internet-gateway --internet-gateway-id $IGW_ID

Terminar la instancia demuestra recuperación: el ASG la reemplaza porque detecta que ya no está running (no por health check del ALB). El cleanup baja el ASG a 0 antes de borrarlo para no dejar instancias huérfanas cobrando.

Ejercicio 2 · Lab 02: ALB + Auto Scaling (hoy en clase)

Usar solo us-east-1. No crear access keys ni key pair SSH. Al final hay que hacer cleanup obligatorio.

Paso 1 · Conectividad mínima

  1. En VPC → Internet gateways, crear dcl-dev-igw-s02 y adjuntarlo a dcl-dev-vpc.
  2. En Route tables, crear dcl-dev-rt-s02-public y agregar la ruta 0.0.0.0/0 → igw.
  3. Asociar las dos subnets a esa route table.

Paso 2 · Security groups

  • dcl-dev-sg-alb: inbound TCP 80 desde 0.0.0.0/0
  • dcl-dev-sg-app: inbound TCP 80 solo desde dcl-dev-sg-alb, sin SSH

Paso 3 · Launch Template dcl-dev-lt-web

  1. AMI Amazon Linux 2023 x86_64, tipo t3.micro y sin key pair.
  2. En Network no fijar subnet, activar Auto-assign public IP y usar dcl-dev-sg-app.
  3. Confirmar Delete on termination = Yes y pegar este user data:
#!/bin/bash
set -euxo pipefail
dnf install -y httpd
TOKEN=$(curl -sS -X PUT -H "X-aws-ec2-metadata-token-ttl-seconds: 21600" http://169.254.169.254/latest/api/token)
INSTANCE_ID=$(curl -sS -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/instance-id)
AZ=$(curl -sS -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/placement/availability-zone)
echo "Digital Café Luna | instance=${INSTANCE_ID} | az=${AZ}" > /var/www/html/index.html
systemctl enable --now httpd

Paso 4 · Target Group dcl-dev-tg-web

  1. Configurar Instances, HTTP:80 y VPC dcl-dev-vpc.
  2. Health check en / con código 200, interval 10 s y healthy threshold 2.
  3. No registrar instancias a mano, porque el ASG lo hace solo.

Paso 5 · ALB dcl-dev-alb

  1. Configurar Internet-facing, IPv4, las dos subnets y dcl-dev-sg-alb.
  2. Crear el listener HTTP:80 con forward a dcl-dev-tg-web.
  3. Esperar State = Active y copiar el DNS name.

Paso 6 · Auto Scaling Group dcl-dev-asg-web

  1. Usar el launch template dcl-dev-lt-web con las dos subnets y adjuntarlo a dcl-dev-tg-web.
  2. Dejar el health check type en EC2, sin activar el de ELB.
  3. Poner min=2, desired=2 y max=4, sin scaling policy.
  4. Validar que haya 2 instancias InService y 2 targets healthy.

Prueba A · Distribución

ALB_DNS=$(aws elbv2 describe-load-balancers --names dcl-dev-alb \
  --query 'LoadBalancers[0].DNSName' --output text)
for i in {1..20}; do curl -s "http://${ALB_DNS}"; echo; done | sort | uniq -c

La salida debe mostrar al menos 2 instance IDs. No tiene que ser 50/50.

Prueba B · Terminación controlada

  1. Anotar los IDs de las 2 instancias del ASG.
  2. Terminar una desde EC2 → Instance state → Terminate. No hay que tocar el desired.
  3. Tener abiertas tres vistas: Target Group → Targets, ASG → Activity y EC2 → Instances.
  4. Seguir enviando curl: el servicio responde desde la instancia que queda.
  5. Ver cómo el ASG lanza un reemplazo, que pasa de Pending a InService y luego de initial a healthy.
  6. Repetir la Prueba A y comprobar que aparece el ID nuevo.
Respuestas de cierre (para defender)
  • Health: decide si un target puede recibir tráfico. No recupera nada.
  • ALB: reparte tráfico solo entre targets elegibles. No mantiene capacidad.
  • ASG: mantiene desired capacity y crea reemplazos desde el Launch Template.
  • ¿Por qué max=4 no escala solo? Porque max es un límite. Sin scaling policy, nadie cambia el desired.
  • No decir que el health check del ALB provocó el reemplazo. El ASG usa el health check de EC2.

Evidencias (capturas)

  • ALB en Active con su DNS, TG con 2 healthy y ASG con 2/2/4
  • Salida del curl con 2 IDs, antes y después de la prueba de fallo
  • ID de la instancia terminada, Activity history con el reemplazo y el ID nuevo en estado healthy

Cleanup obligatorio (en este orden)

  1. Bajar el ASG a min=0 y desired=0, y esperar a que terminen las instancias.
  2. Eliminar el ASG.
  3. Eliminar el ALB y esperar a que se liberen sus ENI.
  4. Eliminar el Target Group.
  5. Eliminar el Launch Template.
  6. Eliminar sg-app y sg-alb.
  7. Desasociar las subnets de la route table S02 y eliminarla.
  8. Desadjuntar el IGW y eliminarlo.
  9. Verificar que solo queden la VPC y las 2 subnets, que son el baseline.
