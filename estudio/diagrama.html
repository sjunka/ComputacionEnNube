Mount target: la puerta de la EC2 hacia el EFS. Es una ENI con IP privada, una por AZ. 
client-a (sg-ec2) ──2049──▶ mount target A (sg-efs) ──▶ EFS
aws efs create-mount-target --file-system-id $FS --subnet-id $SUBA --security-groups $SG_EFS

  1. Crear los SG (sg-efs: 2049 ← sg-ec2).
  2. Crear el EFS.
  3. Crear un mount target por subnet, con sg-efs.
  4. Lanzar las EC2 con sg-ec2.
  5. Montar: sudo mount -t nfs4 <IP del mount target de su AZ>:/ /mnt/efs
Sin el mount target B, client-b cruza a 1a (más costo y un SPOF) o no monta.

Síntomas: ¿qué ve el cliente?

Regla: el cliente solo ve a quien tiene enfrente.

¿Quién está enfrente?Bloqueo (SG / ruta)Servicio caído
EC2 directa (Lab 04: A → B)timeoutconnection refused
ALB (Lab 02: cliente → ALB → EC2)502 / 503502 / 503
  • Timeout = tocas la puerta y nadie abre. El SG tiró el paquete en silencio.
  • Refused = abren y dicen «aquí no hay nadie». Llegaste, pero nada escucha en ese puerto.
  • 502 / 503 = el anfitrión (ALB) dice «la cocina falló». Solo existe si hay ALB.

Ojo: si el bloqueo es en sg-alb (el propio ALB), el cliente ve timeout: el que tiene enfrente no le contesta.
